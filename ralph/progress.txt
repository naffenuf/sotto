  Pacing at 1x goes through an injected `wallClock: Clock` (defaults to systemClock), and
  each delay is computed from the START of the run, like WavReplaySource. Tests pass an
  `instantWallClock(delays)` that records every delay and adds it to its own `now()`, so the
  exact drift-corrected schedule can be asserted ([100, 500, 800, 100, 60]) without waiting.
  CLOCK CHANGE EVERY LATER STORY TOUCHES: `Clock` gained `track<T>(label, work): Promise<T>`.
  It returns `work` unchanged — `const board = await clock.track("board", callModel())` reads
  exactly like the bare call. systemClock's is the identity; SimulatedClock remembers the
  task and `settle()` waits for it. `run()` settles before every clock advance, so simulated
  time never skips over an in-flight model call and the call reads back `now()` as the moment
  it was made. WRAP EVERY AWAITED MODEL CALL IN `clock.track` or the eval harness will race
  past it. Caveat documented on the method: a tracked task must not await one of the same
  clock's timers — nothing moves time while settle waits, so that deadlocks.
  Two pre-existing hand-rolled Clocks in server/asr/realtimeClient.test.ts (heldRetryClock,
  fastRetryClock) needed `track: systemClock.track` added; that is the pattern for any other
